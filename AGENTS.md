# AGENTS.md

Guidance for AI agents (Claude Code, GitHub Copilot, Cursor, etc.) working on this repository.

## Project at a Glance

Django 4.2 backend + React 18 / Vite 4 frontend. Django serves HTML templates that load React bundles compiled by Vite. Two separate React entry points exist (`main` and `todo`). See [CLAUDE.md](CLAUDE.md) for the full project overview.

## Running the Project

Always start **both** servers before inspecting or testing frontend behavior:

```bash
# Terminal 1 — Django (port 8000)
poetry run python manage.py runserver

# Terminal 2 — Vite HMR (port 3000)
pnpm dev
```

## Before Making Changes

1. Read `CLAUDE.md` for architecture context.
2. For backend changes, identify the relevant Django app (`pages/` or `todo/`).
3. For frontend changes, identify which entry point / bundle is affected.
4. Never edit files in `static/dist/` — they are generated by `pnpm build`.

## Backend Guidelines

- **New Django app:** `poetry run python manage.py startapp <name>`, then register in `INSTALLED_APPS` in `mysite/settings.py`.
- **Migrations:** Always run `makemigrations` + `migrate` after model changes. Commit migration files.
- **URLs:** Register app URLconfs in `mysite/urls.py` via `include()`.
- **Settings:** Use `settings.py` for shared config; `settings_local.py` for dev-only overrides. Never hard-code secrets.
- **Templates:** Place in `<app>/templates/<app>/` to avoid name collisions.

## Frontend Guidelines

- **New entry point:** Add it to `vite.config.ts` under `build.rollupOptions.input`, then reference the bundle in a Django template with `{% vite_asset %}`.
- **Shared components:** Place under `frontend/src/components/`.
- **Styles:** App-scoped CSS files alongside components; global styles in `frontend/src/index.css`.
- **TypeScript:** Strict mode is on. No `any` unless absolutely necessary. Use `.tsx` for JSX files.
- **Lint before committing:** `pnpm lint`.

## Testing

```bash
# Backend unit tests
poetry run python manage.py test

# (Frontend testing not yet configured)
```

Write tests in `<app>/tests.py` or a `tests/` subdirectory within the app. Prefer Django's `TestCase` for DB-touching tests.

## Database

| Environment | Database | Config |
|---|---|---|
| Local dev | SQLite3 (`temp_db.sqlite3`) | `settings_local.py` |
| Docker / prod | PostgreSQL | `docker-compose.yml` / `settings_prod.py` |

Never commit `temp_db.sqlite3`.

## Environment Variables

Copy `.env.example` to `.env` and fill in values. The only variable currently required is:

```
DJANGO_SETTINGS_MODULE=mysite.settings_local
```

Production deployments also need `SECRET_KEY`, `DATABASE_URL` (or pg_service config), and `ALLOWED_HOSTS`.

## Docker

```bash
docker-compose up --build    # web (port 8000) + db (PostgreSQL port 5432)
```

The Dockerfile uses Python 3.10-slim. Node/pnpm is **not** inside the container — run `pnpm build` locally and commit `static/dist/` when preparing a production image, or add a multi-stage Node build step.

## Dependency Management

| Ecosystem | Tool | Add command |
|---|---|---|
| Python | Poetry | `poetry add <pkg>` |
| Python (dev) | Poetry | `poetry add --group dev <pkg>` |
| Node | pnpm | `pnpm add <pkg>` |
| Node (dev) | pnpm | `pnpm add -D <pkg>` |

After adding Python packages, commit both `pyproject.toml` and `poetry.lock`. After adding Node packages, commit both `package.json` and `pnpm-lock.yaml`.

## What NOT to Do

- Do not commit `.env`, `settings_local.py`, `temp_db.sqlite3`, or `*.pyc`.
- Do not edit `static/dist/` manually.
- Do not add secrets or credentials to any tracked file.
- Do not break the dual-server dev setup (Django + Vite must both run).
- Do not remove `django-vite` template tags from existing templates without updating the Vite config.

## Current Limitations / Known Gaps

- `todo/models.py` has no models — the todo app is a skeleton.
- No frontend test framework configured (Vitest/Jest not set up).
- No CI/CD pipeline exists yet.
- `Dockerfile` runs `manage.py runserver` — not suitable for production (replace with gunicorn/uvicorn).
